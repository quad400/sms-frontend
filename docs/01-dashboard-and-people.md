# Admin 01: Dashboard and People

Shell: `AdminShell`. Sidebar groups: **Overview**, **People** (Students, Guardians, Staff), **Academics**, **Results**, **Fees**, **Admissions**, **Communication**, **Reports**, **Access and Settings**. Items are permission filtered.

## A1. Dashboard
- **Route:** `/admin` | **Permission:** `reporting.dashboard.read`
- **Layout:** top row of 4 KPI cards (Students enrolled, Attendance today, Fees collected this term, Outstanding balance). Below, two columns. Left: attendance trend (14 days line chart) and enrolment by level (bar chart). Right: "Needs attention" list (open reconciliation exceptions, registers not submitted today, result sheets awaiting approval, unpaid acceptance offers) and the latest announcements. Cards that the user has no permission for are omitted, not blank.
- **Data:** `GET /reports/dashboards/overview`, `.../attendance`, `.../fees`, `.../enrolment` (parallel). Campus filter from the shell.
- **Actions:** each KPI and list row deep links to the relevant filtered page.
- **States:** snapshot cards show "Updated 6 min ago" from the snapshot timestamp. Skeletons on load.

## A2. Students list
- **Route:** `/admin/students` | **Permission:** `students.student.list`
- **Layout:** page header with title, count, buttons **Add student**, **Import** (opens the import wizard C1), **Export**. Filter bar: search, campus, class, status, house. Table below.
- **Columns:** photo, student number, full name, class, campus, status badge, primary guardian phone, balance badge (only with `fees.account.read`), row menu (View, Edit, Archive).
- **Data:** `GET /students?page&pageSize&sort&q&classId&campusId&status` and `GET /classes` for the filter.
- **Actions:** archive `DELETE /students/:id` (ConfirmDialog). Bulk select then Export `POST /exports`.

## A3. Add and edit student
- **Route:** `/admin/students/new`, `/admin/students/:id/edit` | **Permission:** `students.student.create` or `.update`
- **Layout:** two-column form with sections: Personal, Contact and address, Guardians, Enrolment, Medical (separate card, only with `students.medical.update`), Photo.
- **Fields:** first name, middle name, last name, date of birth, gender (lookup), campus, house, class and session (creates the enrolment), photo, guardians (repeatable: search existing guardian or create new, relationship, primary contact, can pick up, fee payer).
- **Actions:** `POST /students`, then `POST /students/:id/guardians` for each, `POST /students/:id/enrolments`, photo `POST /files` then attach. On edit, `PATCH /students/:id`. The student number is generated by the backend and shown read-only after save.
- **States:** field errors from `details`. Duplicate warning if the backend returns a 409 with a possible match.

## A4. Student profile (360 view)
- **Route:** `/admin/students/:id` with tab routes | **Permission:** `students.student.read` (tabs gated individually)
- **Layout:** `EntityHeader` (photo, name, student number, class, status, balance, actions: Edit, Transfer, Archive, Print ID card). Tabs below.
- **Tabs:**
  1. **Overview:** key facts card, guardians card, attendance rate, latest result summary, outstanding invoices. Data: `GET /students/:id`, `/guardians`, `/attendance`, `/results`, `/account`.
  2. **Guardians:** table with relationship, phone, primary, pick-up, fee payer. Add `POST /students/:id/guardians`, edit `PATCH /students/:studentId/guardians/:guardianId`, unlink `DELETE ...`.
  3. **Enrolment history:** `GET /students/:id/enrolments`. Change class `PATCH /enrolments/:id`. Transfer button opens a dialog `POST /students/:id/transfers` (type, destination, effective date, reason).
  4. **Attendance:** `GET /students/:id/attendance`. Calendar heat map plus a list.
  5. **Results:** `GET /students/:id/results`, with links to report cards from `GET /report-cards?studentId=`.
  6. **Fees:** `GET /students/:id/account` (statement and balance), invoices list, payments, scholarships. Actions link to the fees pages.
  7. **Medical:** `GET /students/:id/medical-info`. Shows a "This access is logged" notice before revealing. Edit `PUT /students/:id/medical-info`. Hidden without `students.medical.read`.
  8. **Consents and data:** `GET/POST /students/:id/consents`, `POST /students/:id/erasure-requests` with a ReasonDialog.
  9. **Audit:** `GET /audit-logs?targetType=student&targetId=:id`. Needs `audit.log.list`.
- **States:** archived students show a read-only banner. A 404 renders the not-available page.

## A5. Guardians
- **Route:** `/admin/guardians`, `/admin/guardians/:id` | **Permission:** `students.guardian.list`, `.read`
- **List columns:** name, phone, email, linked children (chips), portal account status. Search by name or phone.
- **Profile:** contact details form (`PATCH /guardians/:id`), linked children table with relationships, portal account card showing the linked user and a **Send reset link** button (`POST /users/:id/reset-password`, needs `users.user.reset-password`).
- **Data:** `GET /guardians`, `GET /guardians/:id`.

## A6. Staff list
- **Route:** `/admin/staff` | **Permission:** `staff.staff.list`
- **Layout:** header with **Add staff**, **Import**. Filters: campus, job title, status, search. Table: photo, staff number, name, job title, campus, status, user account status.
- **Data:** `GET /staff`. **Actions:** archive `DELETE /staff/:id`.

## A7. Add and edit staff
- **Route:** `/admin/staff/new`, `/admin/staff/:id/edit` | **Permission:** `staff.staff.create`, `.update`
- **Fields:** names, gender, phone, email, job title, campus, hire date, photo, and a "Create login account" switch with role multi-select (`PUT /users/:id/roles` after creation, needs `rbac.user.assign-roles`).
- **Actions:** `POST /staff` (with account option), `PATCH /staff/:id`.

## A8. Staff profile
- **Route:** `/admin/staff/:id` | **Permission:** `staff.staff.read`
- **Tabs:** Overview, **Allocations** (subject by class matrix for the active session, `GET /staff/:id/allocations`, save with `PUT /staff/:id/allocations`), **Leave** (`GET /leave-requests?staffId=`), **Attendance** (`GET /staff-attendance`), **Account** (roles, campus access: `PUT /users/:id/roles`, `PUT /users/:id/campus-access`, deactivate and reset password), **Audit**.

## A9. Leave management
- **Route:** `/admin/leave` | **Permission:** `staff.leave.list`
- **Layout:** two tabs, **Requests** and **Leave types**. Requests table with status filter and a right-hand detail drawer (dates, reason, balance, history) with **Approve** and **Reject** (reason required).
- **Data:** `GET /leave-requests`, `GET /leave-types`. **Actions:** `POST /leave-requests/:id/approve`, `/reject`. Leave types edit `PUT /leave-types`.

## A10. Promotion wizard
- **Route:** `/admin/promotions/new`, `/admin/promotions/:id` | **Permission:** `students.promotion.preview`, `.execute`, `.reverse`
- **Layout:** stepper. Step 1 choose campus, from session, to session. Step 2 preview table (every student with current class, proposed outcome lookup (promoted, repeated, graduated, withdrawn) and destination class). Outcomes are editable per row. Step 3 summary counts and an explicit confirmation. Step 4 progress with `AsyncJobBanner`.
- **Data and actions:** `POST /promotions/previews`, `POST /promotions` (202), poll `GET /promotions/:id`. After completion show **Reverse promotion** (`POST /promotions/:id/reverse`, ReasonDialog).
- **Rules:** require the term to be closed and results published first (warn, do not block).

## A11. Transfers
- **Route:** `/admin/transfers` lists transfers recorded through the student profile. Data: `GET /students?status=transferred` plus each student's transfer history. Creation is only through the profile dialog (A4), so this page is a read-only report.
